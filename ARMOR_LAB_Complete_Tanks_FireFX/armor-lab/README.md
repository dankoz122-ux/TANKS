# ARMOR LAB

Браузерный танковый симулятор (three.js): четыре машины по реальным прототипам, броня и пробитие по углу встречи, 3D-рентген попадания, мастерская в стиле Sprocket и **онлайн-комнаты**.

## Запуск локально
```
node server.cjs        # или start_windows.bat
```
Открыть http://localhost:8000. Нужен Node.js ≥ 18 (npm-пакеты не нужны) и интернет для загрузки three.js с CDN.
Игра по локальной сети: `HOST=0.0.0.0 node server.cjs`, друзья открывают `http://<ваш IP>:8000`.

## Хостинг на Render
1. Залейте папку в GitHub-репозиторий.
2. Render → **New → Blueprint** → выберите репозиторий (подхватит `render.yaml`) — или **New → Web Service**: Runtime *Node*, Build Command `echo ok`, Start Command `node server.cjs`, Health Check Path `/healthz`.
3. Откройте выданный адрес `https://…onrender.com` — WebSocket работает по тому же адресу (`wss://…/ws`), ничего настраивать не нужно.

Важно:
- Состояние комнат хранится **в памяти одного процесса** — запускайте один экземпляр (не включайте масштабирование на несколько инстансов).
- Бесплатный план Render усыпляет сервис после ~15 мин без запросов: первое открытие занимает до минуты, а комнаты сбрасываются. Для постоянной работы — платный план.
- Переменные окружения: `PORT` (задаёт Render), `HOST`, `MAX_PLAYERS` (по умолчанию 12), `MATCH_SECONDS` (600), `OVER_SECONDS` (14).

## Как устроен онлайн
- **Комнаты**: список, быстрая игра, создание своей (карта + режим «все против всех» до 15 фрагов / «команды» до 30). Две постоянные комнаты создаются при старте. Матч 10 минут, затем таблица итогов и новая карта.
- **Одна карта у всех**: сервер выбирает карту и `seed`; `js/shared/world.js` строит из них одинаковые препятствия и укрытия у сервера и у всех клиентов. Разрушенные укрытия рассылаются всем.
- **Одна техника у всех**: игрок присылает тип машины (или проект из мастерской), остальные собирают у себя ту же модель. Параметры серийных машин сервер берёт из своей таблицы (`js/shared/rules.js`), параметры своей машины ограничивает.
- **Сеть**: клиент шлёт своё положение 20 раз/с, сервер проверяет скорость и столкновения (при расхождении возвращает на место) и рассылает снимки 20 Гц; чужие танки рисуются с интерполяцией (≈110 мс задержки). Обрыв связи: 20 секунд на переподключение с тем же танком.
- **Бой**: стрелок считает попадание по чужой модели (броня, угол, рикошет, путь снаряда к модулям) и сообщает серверу; сервер проверяет перезарядку, боезапас, дальность и «пробитие» по мощности снаряда, **сам применяет урон по модулям**, детонацию БК, убийства, счёт, респавн (6 с, защита 3 с) и рассылает результат. Стрелок и цель видят 3D-рентген попадания.
- Огонь по своим в командном режиме не засчитывается.
- Чат (Enter), таблица (Tab; на телефоне — кнопки «ЧАТ»/«ТАБЛО»), лента убийств, пинг/FPS, «САМОУНИЧТ.» для застрявших.

Ограничения: попадания определяет клиент стрелка (как в большинстве небольших игр), поэтому от целенаправленных читов защита только базовая — сервер отсеивает невозможные заявки, но не проверяет геометрию попадания.

## Управление
W/A/S/D — движение · мышь — наведение (клик захватывает курсор) · ЛКМ/Пробел — огонь · R — перезарядка · X — тип снаряда · V / ПКМ — оптика · Enter — чат · Tab — таблица.

## Структура
- `server.cjs` — HTTP-раздача + WebSocket-сервер (без зависимостей), комнаты, правила боя.
- `js/shared/` — общие для сервера и клиента модули: `world.js` (карты, коллизии, точки возрождения), `rules.js` (снаряды, урон, параметры машин).
- `js/mp.js` — клиент онлайн-режима: лобби, удалённые танки, табло, чат.
- `js/game.js` — игровая логика, одиночный полигон с ботами; `js/tanks/*` — модели; `js/ballistics.js`, `js/xray.js`, `js/builder.js`, `js/custom.js`, `js/preview.js`.
- `tools/` — тесты: `npm test` (сервер, 22 проверки) и `python3 tools/e2e/e2e.py` (смоук-тест клиента в Chromium).
